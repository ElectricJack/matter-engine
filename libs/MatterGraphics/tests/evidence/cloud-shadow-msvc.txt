Cloud-shadow CPU reference investigation: clear-crest-48.4.10
Recorded 2026-10-11 (America/Los_Angeles)

Disposition
===========
Fixed the numerical CPU reference with a local scalar accumulator. Retain the
pinned toolchain and all production optimization flags. This is an established
MSVC 19.44.35211 x64 optimized-code defect in the out-of-line helper, not a
rendering algorithm error or a relocation regression. The exact internal
compiler optimization pass is not identified; no claim about other compiler
versions is made.

Cause and bound of the fix
==========================
CloudSelfShadowReference initializes all fields. The helper sanitizes its
inputs, bounds the step count, and performs ordinary float additions into
result.tau_local_full while counting samples. With the finite reproducer
inputs there are no dangling references, uninitialized values, pointer
arithmetic, races, overflow, or invalid clamp bounds. std::clamp's temporary
arguments survive until the assigned result has been copied in the same full
expression. Replacing clamp with a plain sum still reproduces the defect.

The original out-of-line assembly zeroes xmm6 at offset 0x9c. The four-iteration
unrolled loop accumulates in xmm1 and stores that correct value into [rbx+4]
(the returned tau_local_full member) at 0x11f. When the count is divisible by
four, the branch at 0x129 skips the scalar tail, leaving xmm6 zero. The later
addition at 0x1c6 uses xmm6 rather than the completed accumulator. The scalar
tail updates xmm6, so counts with a remainder work. This incorrectly merges
the accumulated value across the two paths. The emitted output contradicts the
source: local=5, coarse=2, total=2. The frozen reproducer fails exactly counts
4,8,12,16,20,24,28,32, with all other counts 0..32 passing.

Accumulating into a separate float and assigning the member once after the
loop makes the unrolled and tail paths carry the same accumulator. Per-step
float arithmetic, sample count, distances, exit state, input sanitation,
coarse-start omission, remaining-coarse clamp, total clamp and exp are retained.
A closed-form sigma*distance replacement was only a diagnostic, not the fix.
No renderer/shader code or optimization flags are changed by the fix.
Repository callers of this helper are CPU reference tests only.

Inlining is relevant: a direct step-grid caller can inline and pass while the
compiler also emits the broken out-of-line copy. The committed regression and
frozen reproducer use a volatile function pointer to exercise that copy with
runtime step counts. This does not disable optimization of the helper.
cloud_shadow_reference_tests.cpp fails 35 assertions against the original
relocated header and passes against the fixed header. The existing full
cloud_shadow_tests.cpp and its assertions/tolerances are byte-identical.

import os
from pathlib import Path
import subprocess


def test_verification():
    directory = Path(__file__).resolve().parent
    phase = os.environ.get('CLOUD_SHADOW_PHASE', 'module')
    if phase == 'linux':
        for name in ('full-gcc-sanitized', 'reference-gcc-sanitized'):
            result = subprocess.run([str(directory / name)], capture_output=True, text=True, timeout=60)
            (directory / (name + '-run.log')).write_text(result.stdout + result.stderr)
            assert result.returncode == 0, result.stdout + result.stderr
        return
    script = subprocess.check_output(['wslpath', '-w', str(directory / 'verify.ps1')], text=True).strip()
    result = subprocess.run(['/mnt/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe', '-NoProfile', '-ExecutionPolicy', 'Bypass', '-File', script, '-Phase', phase], capture_output=True, text=True, timeout=300)
    (directory / (phase + '-run.log')).write_text(result.stdout + result.stderr)
    assert result.returncode == 0, result.stdout + result.stderr
    if phase == 'gpu':
        assert 'validation errors: 0' in result.stdout + result.stderr
        assert 'ALL PASS' in result.stdout + result.stderr
