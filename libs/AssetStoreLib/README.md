# AssetStoreLib (MatterStore)

Content-addressed blob storage in append-only pack files, with a semantic ref
table and LRU eviction against a disk budget.

Design: `docs/lod-vt-redesign-2026-08-04.md` §9. Milestone M5, first half.

**This library stores bytes.** It knows nothing about parts, worlds, LODs,
representations or textures, and it depends on nothing but `libs/MemoryLib`. No
engine headers, no raylib, no Vulkan. It builds and tests standalone.

## Why it exists

Today the engine's cache is a tree of thousands of small files: one open, one
seek and one close per artifact. The design's claim is that grouping artifacts
into pack files and reading them in coalesced batches beats that. The benchmark
in `tests/store_bench.cpp` measures the claim rather than assuming it — see
"Measured" below.

## Shape

    BlobStore    content hash -> bytes, in append-only packs
    RefTable     opaque key -> blob hash + (kind, size, last-access)
    ReadBatch    bounded coalesced reads, with duplicate checksum suppression
    PageCache    validated binary pages retained under a payload-memory budget

### The one invariant

> **The committed index is the only authority on what exists.**

Appends go to the end of a pack. They are unreachable until an index naming them
is renamed into place, so a crash mid-append leaves bytes that no reader can
address — and the next writer truncates each pack back to the extent the index
recorded. There is no recovery scan, no journal replay and no repair path,
because there is nothing to repair. `test_crash_mid_write` kills a real child
process partway through a real append and proves all of that end to end.

### Corruption is a miss, never a crash

Every blob carries a CRC32 of its payload, and the index and ref files carry a
CRC32 of themselves. All three are verified on every read, so a damaged blob
reads back as `Status::Corrupt` with a null pointer, and its neighbours in the
same pack are unaffected. Callers treat `Corrupt` exactly as `Missing`: a cache
miss, re-bake. After a corrupt hit, `repair_blob` appends regenerated bytes
with the same verified content identity; commit and refresh the index to make
the repair visible. Ordinary `put` keeps its inexpensive deduplication behavior.

Each blob record also carries a CRC32 of its own 32-byte header, but no read
path checks it: reads seek straight to the payload offset the index names and
never parse a header. It exists so a pack could be rebuilt by scanning if the
index were ever lost — forensic metadata for a salvage tool, not a check that
runs today.

### Concurrency

Single writer, many readers, enforced by a cross-process lock on
`<dir>/store.lock`. A `BlobStore` object is not thread-safe — open one read-only
handle per reader thread. `reload_index()` is how a reader picks up the writer's
commits, and it is all-or-nothing against the writer's rename. Read-only
handles also hold a shared `readers.lock` maintenance lease. Compaction refuses
to run until these handles retire, and writer-open recovery skips old-generation
sweeping while a reader can still lazily open an old pack. Opening a reader
while maintenance holds the exclusive lease fails and may be retried. The empty
lease file can be created by a reader; payloads and indexes remain read-only.

### Async

`ReadBatch::submit()` is **synchronous**. The batching, physical-order sort and
coalescing — the parts that carry the performance — are all present, and the API
shape is the one an async implementation needs. Nothing pretends to be async:
there is no future, no callback and no completion queue that would have to be
redesigned. Adding `submit_async()`/`poll()` (IOCP on Windows, per the design) is
an additive change to the same class.

## On-disk layout

    <dir>/store.lock        writer lock
    <dir>/readers.lock      shared reader / exclusive maintenance lease
    <dir>/p<gen>_<id>.pack  append-only blob records
    <dir>/index.bin         the authority: hash -> (pack, offset, length, crc)
    <dir>/refs.bin          key -> hash + metadata

Byte layouts are documented in `src/store_format.h`. Every integer is
little-endian and written byte at a time, and no structure contains a timestamp,
so the same sequence of writes produces byte-identical files — asserted by
`test_determinism`.

    make -C libs/AssetStoreLib test     # the correctness suite
    make -C libs/AssetStoreLib bench    # the pack-vs-small-files measurement

The archive deliberately does **not** contain MemoryLib's objects: consumers that
already compile `mem_arena.c` would get duplicate symbols. Link the `.a` and keep
compiling MemoryLib from where it lives, per CLAUDE.md's "Code Sharing Between

## Binary asset pages

`include/asset_pages.h` adds a versioned, uncompressed page envelope with typed
section directories, explicit byte offsets and immutable dependency hashes.
`PageHandle` owns its coalesced allocation; borrowed section views stay valid
through cache eviction while that handle is retained. Payload accounting includes
holes/padding and externally pinned allocations, and excludes index/container
metadata. Oversized read batches return `BudgetExceeded`; split or defer them.
This service is thread-confined and synchronous: use it on streaming workers.

`put_batch` bounds staging and performs one append per touched pack. Publish
pages before `publish_page_manifest`, which commits the blob index before the
semantic reference. Readers use `read_manifest` to load references before
refreshing their index snapshot. Use `compact_page_store` for dependency-aware,
quiescent maintenance; ordinary `RefTable::compact` does not trace dependencies.
All required survivors must validate before page-store compaction can publish.

The CPU geometry compiler in `MatterEngine3/src/geometry/` now consumes this
library. Production PartStore/world streaming, GPU residency, and the older
PartBundle/settle/texture cache migrations are still pending.

Native Windows validation:

```bash
./tools/build-windows-from-wsl.sh RelWithDebInfo matter_asset_store_tests
./MatterEditor/build/cmake/windows-msvc/relwithdebinfo/matter_asset_store_tests.exe
./MatterEditor/build/cmake/windows-msvc/relwithdebinfo/matter_asset_store_tests.exe --page-bench
```

The page benchmark compares first page-cache reads (OS cache warm after writing)
with retained validated RAM reads. It is not a cold-disk or engine frame-time
benchmark. It reports 64 KiB, 256 KiB and 1 MiB pages on the same 32 MiB volume.

### Preallocated page payload banks

`PageCacheConfig::bank` optionally shares a `PageBank` created during session
initialization. Reuse it when reopening caches: live handles from older caches
continue to charge the same physical bank. Without an explicit bank,
`PageCache::open` creates one fixed bank using `resident_bytes` (8-byte quantum).
Geometry streaming explicitly supplies a persistent bank with a 256-byte
quantum. This changes runtime allocation, not the disk page format.

Read batches go straight into bank leases. Cache clear/eviction releases lookup
ownership; externally retained handles keep their bytes and rounded capacity.
Local cache budgets and shared bank capacity both apply. Unpinned local ranges
can be evicted to satisfy a contiguous allocation; externally pinned ranges
cannot. Admission returns `BudgetExceeded` instead of allocating another bank.
Read-only page handles may retire on other threads; bank lease operations are
serialized. Other PageCache operations remain thread-confined.

`PageCacheStats::bank` reports global bank occupancy and fragmentation, while
`resident_payload_bytes` reports this cache's live payload leases. Container,
index, decoded mesh and Vulkan allocations are outside this payload contract.


`PageCacheConfig::read_ahead_bytes` optionally expands the first cold demand to
its bounded group of physical neighbors. Groups follow pack order and are
rebuilt on index snapshot changes. Individual records retain their hashes and
CRC/page validation. The cache keeps valid speculative pages for later hits;
corrupt neighbors do not invalidate an otherwise valid requested page. Demand
results preserve caller order. Expansion is removed if its rounded allocation
cannot fit without eviction or exceeds the batch read limit. This is physical
read-ahead, not a sector manifest or a new disk format.
